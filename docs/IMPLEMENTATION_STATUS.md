# Bear Den TV implementation status

This page says what exists today, what is tested and what has been seen working on your TV.
Those are three separate claims:

- **Implemented**: the code is in the tree.
- **Automatically tested**: a named test exercises it and runs in `make test` (or `scripts/e2e-target.sh` for the live suite).
- **Live on the TV**: a commit message or doc records it working on the real TV. If not, the row says "not yet seen on the TV".

Requirement ids (such as `UI-02`) come from the original design brief's acceptance matrix, which is not part of this repository.
Commands are explained in [`operations.md`](operations.md).

### Incident: the coordinator frozen in state T (reported 2026-09-29)

- **What was seen on the TV** (the packaged build, started by `/usr/lib/bear-den-tv/start-session.sh --watch` over ssh): `bear-den-tv session` in state `T (stopped)`, wchan `do_signal_stop`, all 11 threads stopped, parent pid 1. Its log stopped at about 08:03 and nothing followed until 18:06, so Bear Den was frozen for up to about 10 hours; the frozen shell stayed on top and the owner saw windows that could not be closed. SIGTERM and SIGQUIT did nothing until SIGCONT. The user journal did not show who sent the stop. The watchdog restarted only a coordinator that *exited*, and `start-session.sh stop` sent SIGTERM (held by a stopped process) matched with `pkill -f` patterns, so neither helped.
- **Root cause: not found.** Ruled out here, on the workstation:
  - Bear Den sends no stop signal: the Go, C++ and script sources send only SIGTERM and SIGKILL (to their own children's process groups: the shell, the web apps' browser, the Widevine first run, installs) and `flatpak kill` of one app instance.
  - The start script's layout already made terminal stops impossible: the watchdog is a session leader (`setsid`) without a terminal and the coordinator is in its process group, whose parent is outside the session, so the kernel discards SIGTSTP, SIGTTIN and SIGTTOU for it. Reproduced: those three leave it running, only SIGSTOP stops it (`TestStartSessionDetachesFromTheTerminal`).
  - So it was SIGSTOP from outside Bear Den, or a coordinator started some other way (by hand from a terminal): the log cannot tell which. Parent pid 1 means no watchdog was its parent any more (or it was never started by one). The old watchdog would not have noticed anyway: bash's `wait` does not return for a stopped child (reproduced).
- **Found on the way and fixed:** started from a terminal that closes right away (`ssh -t`, a terminal window), the script could lose the start: the kernel hung up the `setsid` child (SIGHUP) before it had its own session. The script now waits until it has.
- **Mitigated by** (all automatically tested, **none yet seen on the TV**): `session` ignores SIGTSTP/SIGTTIN/SIGTTOU (`cmd/bear-den-tv/daemon_test.go`); the watchdog restarts a coordinator that is stopped or does not answer `bear-den-tv doctor --ping` three times in a row, with SIGCONT, SIGTERM, then SIGKILL, and logs each step ([operations → The watchdog](operations.md#the-watchdog); `tests/packaging/watchdog_test.go`, `internal/shellipc/alive_test.go`); `stop` continues before it terminates, kills after 10 s, and matches by executable, not by command-line pattern. A stopped coordinator is now replaced within about 30 s (10 s more if it needs SIGKILL), one that stops answering within about 2 minutes (3 checks 30 s apart, 5 s each); until then the frozen shell still sits on top.

### Known test gaps

Checked in the tree on 2026-09-29:

- `internal/remote` (HTTP/WebSocket server, auth, rate limits) has only a route-table test (`routes_test.go`: no route issues invitations, guests fail every permission gate) and the app icon route's test (`appicon_test.go`, the real server with `remote/testutil` fakes); `internal/pairing/guest_remote_test.go` drives the real server for the guest pass end (close 4001). There is no negative suite for cookies, CSRF, Host/Origin, rate limits or revocation timing. `internal/remote/mdns` has `mdns_test.go`.
- `internal/doctor` has no tests.
- The shell supervisor's crash/restart path has no test; `internal/shellipc/supervisor_test.go` only checks the environment allow-list.
- The phone remote's browser suite (`apps/remote-web/tests/e2e`, Playwright against `bear-den-tv dev --dev-fixtures --no-shell`) is one flow: pair by code, DEMO apps, open an app, Now playing, one D-pad key. Pairing errors, guest passes, the editor, installs and the touchpad are covered by Vitest only. The web apps' navigation script, `apps/web-nav`, has Playwright tests on local fixture pages.
- `start-session.sh stop` refusing to go on when a process survives SIGKILL (state D) has no test; nothing here can make such a process.
- `make lint` always runs qmllint (it configures `build/tv-shell` when missing) but reports its warnings without failing.
- Not in `make test` (need Docker, a TV or a live display): `packaging/smoke-deb.sh`, `scripts/wayland-container-test.sh`, `scripts/e2e-target.sh`, the live DPMS test.
