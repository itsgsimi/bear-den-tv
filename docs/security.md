# Security model (LAN remote and desktop control)

## Assets and trust boundaries

- **Desktop input and window control** on the TV machine: reachable only through the coordinator's action router. The phone never sends keycodes, shell strings, paths, URLs, or scripts; it sends named actions validated against [`contracts/action.schema.json`](../contracts/action.schema.json) (the list is in [`contracts/actions.md`](../contracts/actions.md)).
- **Private state** (focus, layout, device list, content rows, what is playing): visible only to authenticated devices, redacted by permission, and withheld entirely while the desktop session is locked.
- **What is playing (Now playing on phones)**: a deliberate exception to "phones never see external window titles". While an app in front exposes an MPRIS player, paired phones with the `controller` permission (or higher), and guest passes, see its title, artist or album, length, position and play/pause state (`state.now_playing`, [`contracts/http.md`](../contracts/http.md#now-playing-statenow_playing)). Anyone holding such a phone can therefore read what is on the TV. Only the foreground app's own player (matched by its adapter, as media buttons are) is read, never another player on the bus. It is omitted while the desktop is locked, for the shell, CLI peers, anonymous viewers and phones with neither `controller` nor a guest pass, and whenever the owner turns it off (TV Settings → Now playing on phones, config `remote.now_playing`, on by default). The reading lives only in the coordinator's memory: it is not written to `config.json`, SQLite, logs, diagnostics or exports, and the types that carry it print `[title]` in place of titles. `target.window_title` stays redacted for apps.
- **Secrets**: paired-device session tokens are stored as SHA-256 hashes; invitation tokens/codes are single-use with expiry and attempt limits; Plex tokens live in the Secret Service, never in `config.json`, exports, logs, or phone payloads.
- **Plex (outbound, after sign-in only)**: nothing is sent to Plex until the owner chooses Sign in in TV Settings → Plex (or runs `bear-den-tv plex sign-in`). Then the coordinator talks to plex.tv (`POST /api/v2/pins` for a link code, `GET /api/v2/pins/{id}` every 2 s until it is linked or expires, `GET /api/v2/resources` for the account's servers) and, from the moment the owner picks a server, to that server only (`/identity`, `/library/sections`, `/hubs/continueWatching` or `/library/onDeck`, `/library/sections/{id}/recentlyAdded`, `/photo/:/transcode` for posters). Rows refresh when Home comes to the front and every 10 minutes while it stays there, never while an app or another screen is in front; failures back off up to 10 minutes. The token goes into the desktop keyring (Secret Service) under `plex_content.connection_ref`, only ever travels in the `X-Plex-Token` header, and never reaches `config.json`, logs, diagnostics, the shell or phones. Without a usable keyring sign-in fails closed ("Plex sign-in needs a keyring; install or enable gnome-keyring") and nothing is sent; no file fallback exists. The link code and the sign-in flow (`state.plex`) are shown on the TV only. Phones do see the Home rows (`state.content`: titles, subtitles, progress, and poster paths on the TV they cannot fetch), like the rest of Home. Sign out deletes the token, turns `plex_content` off and deletes the cached posters. Plex HTPC keeps its own sign-in; Bear Den never touches it.
- **Location (local weather)**: off by default. Only when the owner turns weather on (TV Settings → Weather or `bear-den-tv weather set`) does the coordinator make outbound HTTPS requests (10 s timeout, `User-Agent: bear-den-tv`, no cookies or account), to Open-Meteo only (`api.open-meteo.com` for the reading every 30 minutes, `geocoding-api.open-meteo.com` for a place search the owner types). No key or account exists; the endpoints are constants in `internal/weather`, never configuration. Coordinates are rounded to 2 decimals (about 1 km) before they are stored or sent, are never logged, and never reach phones: `state.weather` is shell-only and hidden while locked. Open-Meteo sees the TV's public IP address and the rounded location, as any web service would. Nothing new listens. Settings: [`contracts/config.md`](../contracts/config.md); commands: [`docs/operations.md`](operations.md#local-weather).
- **LAN listener**: off until onboarding consent; bound only to the addresses of the selected interface; loopback-only in development mode.

## Controls (where enforced)

| Threat | Control | Location |
|---|---|---|
| Unpaired LAN device controls the TV | cookie session + per-request authorization; anonymous routes are `/`, `/api/v1/info`, `/api/v1/pair/claim` only | `internal/remote` |
| Brute-forced pairing code | 6-digit code + 5 attempts per invitation, 2 min expiry, per-source rate limit, invitation issued only from the TV/CLI | `internal/pairing`, `internal/remote` |
| CSRF from another site on the phone | `SameSite=Strict`, `HttpOnly` cookie + `X-BDTV-CSRF` header bound to the session; no state change on GET | `internal/remote` |
| DNS rebinding / wrong host | `Host` allowlist (bound literals + configured names) → 421; `Origin` allowlist on state changes and WebSocket upgrades → 403 | `internal/remote` |
| Sniffing/modification on HTTP mode | documented limitation; HTTPS preferred; on `trusted-lan-http` no credential entry, no device admin, no diagnostics, layout editing only if explicitly enabled | `internal/remote`, UI copy |
| Revoked device keeps a socket | revocation closes WebSockets (4001) and invalidates sessions within 1 s | `internal/remote`, `internal/pairing` |
| A guest pass does more than a visitor needs | a guest device holds only `guest` (never with `controller` or higher: schema rule, `pairing.normalizePermissions`, `Grant` refuses it both ways, `remote.Viewer.Has` treats any viewer listing `guest` as guest-only). Actions go through the `contract.GuestActions` allow-list (navigation, `select`, `back`, `home`, `app.launch`, media play/pause/seek, volume, mute, `text.submit`): `app.close` in any mode, `shell.restart` and every action not listed, including ones added later (power, display), fail with `forbidden`. Every `perm`-gated route (layout, devices, diagnostics) refuses guests; guests never receive `devices`, `layout`, `pairing`, `playback` or `weather`, but do receive `now_playing` (they watch the same screen). Tests: `internal/session/guest_test.go` (`TestGuestMaySendOnlyTheAllowList` walks `AllActions`), `internal/remote/routes_test.go` | `internal/contract`, `internal/session`, `internal/remote`, `internal/pairing` |
| A guest pass outlives its end | the end is stored (`devices.expires_at_ms`, schema 2) and enforced three ways: `Authenticate` refuses and revokes an ended pass on every HTTP request; a timer on the injected clock revokes at the end (and wakes at least every 5 min, so a suspended box or clock change is caught soon after waking); the action and hold gate refuses an ended pass on sockets opened before the end; `pairing.New` revokes passes that ended while the coordinator was stopped. Revocation is the ordinary path (sessions deleted, `revoked` + close 4001, holds cancelled). Tests: `internal/pairing/guest_test.go`, `guest_remote_test.go` (4001 over the real server), `TestEndedGuestPassRefusesActionsAndHolds` | `internal/pairing`, `internal/session`, `internal/remote` |
| A phone or guest issues invitations | no HTTP route issues invitations (only `/api/v1/pair/claim` redeems); `pair.issue`, with or without a pass, is accepted only on the private IPC socket from the shell or the local CLI. Test: `TestPhonesCannotIssueInvitations` | `internal/remote`, `internal/session` |
| Input routed to the wrong window | target resolved from observed foreground; unknown/locked ⇒ refuse; XTEST delivery re-verifies `_NET_ACTIVE_WINDOW` immediately before each tap | `internal/actions`, `internal/platform/x11` |
| Stale/replayed presses after reconnect | context epochs; dedup with payload comparison; holds are server leases that die on disconnect/hide/lock/epoch change; reconnect fetches state, never replays | `internal/actions`, `apps/remote-web` |
| Killing unrelated processes | close = WM_DELETE on the tracked window; force = `flatpak kill <instance>` only | `internal/applications/flatpak` |
| Secret leakage via logs/exports | Plex `Redactor` strips the account token and item titles from logs, diagnostics and state messages; exports contain the portable layout only; config validator rejects `token`, `x_plex_token` and `password` keys | `internal/providers/plex`, `internal/config`, `internal/session` |
| SSRF via artwork/metadata | provider fetches only the configured Plex server host; redirects to other hosts refused; thumbs must be server-relative paths; artwork is size-, type- and dimension-checked before it is cached; no generic fetch endpoint. Tests: `TestPhotoRefusesRedirectToAnotherHost`, `TestPhotoRejectsUnsafeThumbsAndNonImages`, `TestAccountRefusesRedirectToAnotherHost` | `internal/providers/plex` |
| Plex traffic without the owner's say, or to the wrong server | the connector sends nothing until sign-in; the keyring is checked before plex.tv is contacted; a chosen server is kept only if its `/identity` names the machine plex.tv listed (an impostor connection is skipped); relay connections are never used; rows never refresh behind an app. Tests: `TestSignInLinksStoresTheTokenAndWritesConfig` (no request before sign-in), `TestSignInWithoutAKeyringFailsClosed`, `TestChooseAmongSeveralServersProbesConnections`, `TestRefreshCadenceFollowsHome`, `TestPlexRowsOnlyRefreshBehindHome` | `internal/plexlink`, `internal/session/plex.go` |
| Plex token or link code leaking | token in the keyring and the request header only (`TestTokenTravelsOnlyInTheHeader`, `TestTokenNeverReachesLogsOrErrors`, config.json checked in `TestSignInLinksStoresTheTokenAndWritesConfig`); `state.plex` has no token field (`state.plex-token-field.invalid.json`) and is shell-only (`TestPlexSignInOverIPCAndRowsOnHome` checks every phone view) | `internal/providers/plex`, `internal/plexlink`, `internal/session` |
| Media titles leak via phones, logs or diagnostics | `state.now_playing` for `controller` phones and guest passes only, never while locked, never for the shell (so never in `doctor` or `/api/v1/diagnostics`), and absent when the owner turns it off; only the foreground app's own MPRIS player; memory only; `contract.NowPlaying` and `platform.MediaInfo` print and log `[title]`; the MPRIS probe listing carries no titles. Tests: `internal/session/nowplaying_test.go` (`TestNowPlayingNeverLoggedOrInDiagnostics` and the view, lock, setting and foreground cases), `TestNowPlayingNeverPrintsTitles`, `TestListNeverCarriesTitles` | `internal/session`, `internal/contract`, `internal/platform/mpris` |
| Location leak via weather | off by default; requests only while enabled, only to the Open-Meteo constants; coordinates rounded to 2 decimals (config rule 10) and absent from logs, errors, diagnostics and phone payloads; `weather.search`/`weather.configure` accepted from trusted local IPC peers only | `internal/weather`, `internal/session`, `internal/config` |
| Executable themes/plugins | none exist; layout is data ([`contracts/layout.schema.json`](../contracts/layout.schema.json)); themes are data packages with no code ([`docs/THEMES.md`](THEMES.md)) | — |
| Unrestricted IPC | Unix socket 0600 in a 0700 dir, `SO_PEERCRED` uid check, protocol handshake, 256 KiB frames, one shell client | `internal/shellipc` |
| Remote unlock of the desktop | never implemented; `home` is refused while locked | `internal/actions` |
| Sleep timer or screen off used to act behind the lock screen | while locked the phone's `power.sleep_timer` and `display.off` are refused like every action; a timer set before the lock only turns the display off (no pause, no Home); a phone press still turns an off display on, which then shows only the lock screen. Turning the display off never locks or unlocks anything | `internal/session/power.go` |
| The screen-waking press acting on an app | the press that wakes a display Bear Den turned off is swallowed (`failed/display_off`); on the TV the shell swallows it when in front. A TV key with an app in front does reach that app (documented) | `internal/session/power.go`, `apps/tv-shell/qml/ShellRoot.qml` |
| Desktop power settings left changed | DPMS enabled only while the display is off, with 0 timeouts; the exact previous state is restored on wake and on coordinator stop; a killed coordinator leaves DPMS enabled with no timeouts (nothing blanks) | `internal/platform/x11/dpms.go` |
| Handling the session password to suspend | never: logind `CanSuspend` is only asked, and "challenge" is reported as unavailable | `internal/platform/suspend` |

## Den badges

Den badges ([`contracts/http.md`](../contracts/http.md#den-badges-stateachievements)) are the one place Bear Den counts how it is used, so they are built to say as little as possible:

- **What phones see:** badge ids, counts toward each badge (capped at its goal) and the local calendar day each badge was earned. Never a time of day, never titles or anything an app reports it is playing, never a per-day history. Only the shell and phones with `controller` get `state.achievements`; guest passes never do (the schema rejects it) and nobody does while the session is locked.
- **Off switch:** config `achievements.enabled` (TV Settings → Badges, on by default). Off counts nothing at all.
